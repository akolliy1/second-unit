        Investigation

        Five agent stages run in a fixed order, and each hands the next a typed object rather than prose — so a stage cannot quietly reinterpret its predecessor's opinion.

        What you are watching

        • Watchtower — what is abnormal. Breadth only; it is explicitly told not to diagnose, because a premature guess poisons everything downstream.
        • Diagnostician — why, and it must rule things out. The asset pipeline emits warnings all through the incident; they start before it, so they are noise. Watch for that row.
        • Impact Forecaster — the delivery consequence. The arithmetic is a Python function, not the model, and it refuses inputs it cannot believe.
        • Remediation Planner — the fix and the proposed write-back. It holds no write tools at all.

        Where the numbers come from

        Every claim carries the tool call and the exact PromQL or LogQL that produced it, against a live Grafana Cloud stack through the Grafana MCP server. Nothing is cached; nothing is mocked. The review deadline is read from telemetry (shot_review_deadline_seconds) — a commitment the agent discovers rather than one we hand it.

        The approval gate

        Nothing is written until you approve it, and that is structural rather than a promise: the stage that proposes writes has no mutating tools, and the executor that does is only constructed once an approval record exists naming who approved which items. An unapproved run has no privileged surface at all.

        Approved writes are then checked out of band — through Grafana's HTTP API, not the MCP tools the agent just used — and disagreements are reported. See the Agent page.

        Recorded vs live

        The page loads a real recorded run, so there is a finding on first paint. Add ?live=1 to run the agents now against current telemetry — that costs Vertex quota and takes roughly three minutes. If quota is exhausted the stream says so and points back here rather than failing silently.

        The dailies briefing

        The same finding, spoken, in about fifty seconds. The script is composed in Python from the stage outputs — not generated by a sixth model call — so every number in it has already been computed and verified.
